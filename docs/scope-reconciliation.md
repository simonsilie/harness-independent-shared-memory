## What no longer governs implementation

The protected OS identity, separate reviewer credentials, multi-user authorization, team publication and team deployment are not requirements of this personal workflow. Their existing code and probes are retained as historical implementation and evidence, not work that must be completed before productive use.

Separate immutable proposal objects, a permanent review-decision ledger, full historical revision export and a particular MCP facade are implementation choices rather than requirements established by the ADRs. Conflict detection, approval of the presented durable content, useful provenance, archive behavior and portable content remain requirements. Removing enforcement does not remove these behaviors.

The former ten-session/two-repository/seven-day gate, mandatory daily use of all three clients and read-only-before-capture phase sequence are superseded by productive use with ongoing observations. No new numerical threshold or review date is introduced here.

## Implementation conclusion

The existing evidence supports using Basic Memory as the first candidate, but does not yet justify either the complete custom workflow or claiming that native Basic Memory satisfies every revised requirement. The concrete unresolved checks are model-free operation, conditional updates through the actual clients, personal-plus-project recall, and the full temporary/archive lifecycle and export content. These are configuration/API/behavior checks against an installed candidate, not reasons to start another artificial pilot project.

Configure the smallest existing-tool path that satisfies those checks and the agreed global client behavior. Carry out ordinary work while collecting lightweight observations. Only a reproducible shortfall against a row above justifies a focused adapter; existing code can be reused if it is the smallest solution. No runtime code, dependency, global configuration or memory content is changed by this reconciliation.

The original architecture file remains a pinned corpus source in [preparation tool](../evaluation/recall/prepare.py). Its old contracts must not override the ADRs. On 18 November 2026 the working copy's single section 8 wording change was reconciled deliberately: the affected preparation summary and `memory-18` were reviewed and updated, the pin and all corpus source revisions were advanced, and a fresh derivation in a temporary directory confirmed the questions and answer key byte-identical ([provenance record](source-provenance.md)). Preparation was not rerun, and historical evidence keeps its original revisions.

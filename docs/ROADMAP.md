# Personal shared-memory roadmap

This is the working backlog for the [agreed scope](scope-reconciliation.md). Former stage-based planning no longer organizes current work: productive use and evaluation run together. Retained reports and raw evidence remain historical references, without inherited rollout gates.

Unchecked items below remain open. Documentation and past isolated tests do not complete productive setup. Preserve existing user data and configuration; this roadmap does not itself install software, enable writes or move memory.

Explicit text query mode and per-note opt-out alone are insufficient evidence. Record configuration, result and remaining limitations. See ADR 0007 and the existing native probes.
  - [17 November installed-package verification](model-free-operation.md#approved-local-installation): the owner-approved [local patch](../patches/README.md) is installed in the project environment. `semantic_search_enabled=false` passed MCP startup, write/text search, watcher indexing, restart and CLI checks against that installation, with the SQLite vector extension available and zero inference imports, outbound connections or model downloads. External-store activation remains a separate storage task; this is a locally patched version, not an upstream release.
- [x] **Verify conditional writes through Codex and OpenCode.** Check creation and updates using native checksums, including two sessions changing the same entry: the stale write must conflict and preserve the newer content. Use existing concurrency evidence where applicable; verify the chosen client path rather than rerunning the former protected-review suite. See ADR 0008.
  - [17 November native client check](native-client-writes.md): both clients created and updated notes; both stale writes returned `REVISION_CONFLICT` and preserved the winning database and files. Verified against disposable storage with the model-free fallback guard; productive configuration remains open.
- [x] **Check native coverage of the remaining memory behavior.** Map personal defaults plus project-scoped recall, explicit cross-project lookup, temporary/archive lifecycle and complete export content to concrete native operations and configuration. Separate product gaps from missing client instructions. For each remaining gap, record the requirement, reproduction and smallest remedy before choosing an adapter or alternative. Do not deploy the complete existing workflow by default. See the [reconciliation table](scope-reconciliation.md#requirements-against-existing-behavior).
  - [17 November native coverage check](native-memory-coverage.md): scoped combined recall, metadata filtering, conditional restore and per-project OKF exports passed with disposable notes. Automatic lifecycle remains caller behavior to implement and verify; global model-free configuration and productive setup remain open.

These checks determine the smallest implementation to configure. They are targeted checks, not a separate pilot project or a requirement to revive the former phase sequence.

## Configure productive use

- [x] **Choose and configure external local storage.** Select a user data directory outside all repositories and version control for durable knowledge, temporary context, archive and observation log. Keep one authoritative memory store; preserve the historical corpus in this checkout. Record the actual paths and storage configuration. See ADR 0006.
  - [17 November storage activation](external-storage.md): native SQLite storage under `$HOME/SharedMemory` activated with `semantic_search_enabled=false`; both projects, native writes, watcher indexing, scoped/combined text search and restart verified without inference or network access. Temporary check notes removed; existing stores and client connections preserved.
- [x] **Configure shared behavior once per client.** Connect Codex and OpenCode to that store. Install common instructions for startup and mid-task recall, project selection, sources and conflict reporting, visible nonblocking outages, and explicit chat approval before durable writes. Temporary saves need no individual approval. Verify the actual tool surface and ordinary session behavior; a separate reviewer identity is not required. See ADRs 0002, 0004, 0005 and 0010.
  - [17 November client connections and behavior checks](client-connections.md): global and active project configurations use the external store through the shared toolbox launcher. Both real clients verified topic-triggered scoped recall with sources, a concrete proposal followed by separate chat approval, temporary capture without individual approval, and continued work with visible reporting of relevant missing memory during an outage. Write and outage checks used disposable stores with the installed common instructions; approval remains a workflow convention, and lifecycle verification remains separate.
- [x] **Make personal defaults reusable across projects.** Store owner-approved preferences, including Python guidelines, with available provenance. Confirm ordinary recall combines these defaults with the current project's knowledge without importing unrelated handovers. Current project rules take precedence; avoid copying the same preferences into every repository. See ADRs 0004, 0010 and 0011.
  - [17 November adoption and verification](personal-defaults.md): after explicit chat approval, both source-backed notes were saved once in productive `personal` storage; native reads, combined active text recall and comparison with the approved drafts passed. Both clients previously verified combined personal/current-project recall, exclusion of foreign handovers and precedence of actual project rules across the two existing checkouts using one disposable store. An OpenCode invocation fix aligns `PWD` with the selected checkout; retained failures and checks are documented.
- [x] **Complete temporary context and archive behavior.** Save and resume work across sessions; exclude completed handovers immediately and inactive entries after seven days unless explicitly extended. Updates refresh the inactivity window. Keep the archive explicitly searchable and restorable, exclude it from ordinary recall, and retain its contents until owner-requested deletion. Verify conflict detection also applies to updates. See ADRs 0003 and 0008.
  - [17 November activation and real-client checks](temporary-context.md): after owner approval, the verified lifecycle rules were activated in the common toolbox AGENTS file. Both clients passed post-activation scoped recall and expiry/archival checks without an instruction override, using disposable stores and leaving productive notes unchanged. Earlier checks cover capture/fresh-session resumption, activity updates, extension, completion, explicit archive search and restore; two native sessions verified stale temporary-update conflicts. The separately approved frontmatter-reset finding was saved and verified in project memory.
- [x] **Enable lightweight automatic observations.** Use the [ADR 0012 JSONL format](adr/0012-automatic-lightweight-handover-observations.md) outside repositories. Record continuation evidence, misses, reminders and unknown outcomes; keep agent assessments distinct from optional owner feedback. Start with existing tools; add a small writer only for a demonstrated reliability gap. Verify concurrent sessions can record without losing or corrupting observations.
  - [18 November activation and verification](automatic-observations.md): after owner approval, the shared rules were activated for both clients using existing Python tools. Twelve processes appended 384 observations without loss or corruption. Both actual clients automatically recorded capture, unprompted partial continuation and completion with separate owner feedback; synthetic checks preserved productive notes and logs. Everyday usefulness remains a later review task.
- [x] **Make the model-free runtime build reproducible.** Combine the uv-locked Basic Memory version and the seven-file semantic-disable patch in one versioned build step, then verify the built package in a fresh environment with the existing MCP watcher check. Deploying it into the launcher runtime remains a separate decision.
   - [18 November build and fresh-environment verification](model-free-operation.md#reproducible-build-verification): `build/semantic_runtime.py build` produces a byte-identical `1.0.0+semantic.1` wheel from the lock pin and patch; `verify` installed it into a fresh environment and the existing watcher probe passed MCP startup, write, text search and zero inference imports or outbound connections. The productive `.venv` and client configuration were unchanged.

Storage and client setup depend on the selected implementation path. Lifecycle and observation work can proceed alongside configuration. Begin useful real-project work as capabilities become available; do not wait for a fixed observation count or require everyday Claude Code use.

## Verify recovery and learn from real use

- [x] **Establish backup and verify restoration.** Choose the local backup procedure for the actual productive data layout. Restore a consistent backup into a separate destination, verify knowledge, project associations, temporary/archive content and rebuilt text search, and leave the live store untouched. Past fixture restores are supporting evidence, not verification of the new paths. See ADR 0006.
  - [18 November productive backup and restore](productive-backup.md): a consistent SQLite snapshot, both project trees, configuration and locked observation-log copy were saved outside repositories and restored into a separate destination. Both project identities, all five productive notes including the archived handover, native reads and rebuilt text search passed; active/archived fixture content and repeatable WAL-safe restores passed isolated tests. Live data and client connections remained unchanged. This establishes an on-demand local procedure, without scheduled or off-device backup.
- [x] **Verify portable export separately.** Document the export format and inspect a complete export including project associations, active handovers and archive. Confirm content is usable outside the original implementation; distinguish this from same-version backup restoration. Search indexes can be rebuilt. See ADR 0009.
  - [18 November portable export](portable-export.md): both productive projects were exported into separate native OKF v0.2 bundles outside repositories. All six notes, including the archived handover and its lifecycle fields, passed `okf check`; there were no active productive handovers. An isolated fixture covered active, expired and archived handovers with no cross-project leakage. A reader using only Markdown, YAML and a database-free text scan reproduced bodies, metadata, project associations and scoped queries; zero inference imports or outbound connections were recorded and the live store stayed unchanged. No alternate-engine import was performed.
- [x] **Review observations from real projects.** Use Codex and OpenCode for actual work while collecting observations automatically. Review successful and failed handovers, useful and missed knowledge recall, reuse of personal defaults, reminders and maintenance burden. Agree a review time during use; no numerical adoption gate is prescribed. Turn reproducible requirement gaps into focused fixes. See ADRs 0011 and 0012.
  - [18 November interim and agreed review date](observation-review.md): the productive log contains one observation of actual continuation during activation of the shared observation rules, not a synthetic observation; no active handovers and no reproducible requirement gap, hence no focused fix. The owner confirmed the first review date — moved forward to 21 November 2026 by the owner on that day — and the working agreement: real Codex/OpenCode work without artificial tasks or a minimum count, handovers arising at real interruptions, misjudgements corrected briefly in chat. Little evidence is itself a result and does not auto-complete this item; only reproducible gaps justify changes ([review record](observation-review.md), [original source](automatic-observations.md#productive-observations)).
  - [21 November review performed](observation-review.md#review-performed-21-november-2026): the date was brought forward to 21 November and the review carried out that day. The productive log held 22 observations across seven handovers from real Codex/OpenCode work: 10 successful, 9 partial, 3 capture-only, no failed. One handover was retrieved after a reminder. The earlier reproducible gap — Codex sandbox denial of observation-log appends — was fixed via `writable_roots` in the Codex config and toolbox template and verified by twelve Codex observations on 20–21 November. No further reproducible gap justifies a change, so the item is complete.

Recovery and export checks run separately from everyday observations. No artificial work project or fixed waiting period is required.

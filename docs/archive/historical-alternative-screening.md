# Historical alternative screening: DrDroidLab Hindsight

This comparison assessed the former contract. The [scope reconciliation](scope-reconciliation.md) supersedes its requirements; rejection against protected review or Git-based storage must not be treated as a new-scope adoption decision without reassessment. No candidate was reevaluated for this update.

DrDroidLab Hindsight supplies a review workflow, but does not satisfy this project's former controlled-capture contract without further work. Switching engines alone would not complete step 2. This is the narrow alternative comparison called for by [architecture section 12](../../evaluation/harness-independent-shared-memory.md#12-build-versus-adopt-decision) after the [Basic Memory native probes](evaluation-results.md#native-prerequisite-probes--15-november-2026); it is not a deployment recommendation or a passed gate.

Inspected on 15 November 2026 at [`bb8704fb6a3ed4e91877e244b2aea6360662621d`](https://github.com/DrDroidLab/hindsight/commit/bb8704fb6a3ed4e91877e244b2aea6360662621d). No package or container was installed, and no candidate runtime was exercised. The domain, model and authentication files read from `main` were checked against that commit. Source review establishes contract differences; operational claims below still require runtime verification.

| Former gate | Candidate capability and remaining mismatch/proof |
| --- | --- |
| Model independence | Manual capture, review and FTS are documented without a model; optional providers have no hosted fallback. Promising, not runtime-tested here. [FAQ](https://drdroidlab.github.io/hindsight/faq/) |
| Cross-client capture | `propose_clue` and CLI capture feed a review queue; HTTP review is explicit. Three-client origin/retrieval tests remain undone. The clue workflow is not the project's separate immutable proposal and durable-revision contract. [API](https://drdroidlab.github.io/hindsight/api/) |
| Pending edits | Proposed clues can be edited in place; the original immutable candidate is not preserved as a separate proposal object by that operation. Proposed clues remain visible, labelled unreviewed, in recall. This differs from accepted-only default recall. [Domain: `edit_clue`](https://github.com/DrDroidLab/hindsight/blob/bb8704fb6a3ed4e91877e244b2aea6360662621d/src/hindsight/domain.py#L370), [content model](https://github.com/DrDroidLab/hindsight/blob/bb8704fb6a3ed4e91877e244b2aea6360662621d/docs/content-model.md) |
| Stale approval | Review checks the current clue's expected blob revision under a lock. This is useful concurrency protection; two immutable proposals bound to the original accepted target revision are not established by it. [Domain: `review`](https://github.com/DrDroidLab/hindsight/blob/bb8704fb6a3ed4e91877e244b2aea6360662621d/src/hindsight/domain.py#L417) |
| Handover | The six supported kinds are service, runbook, clue, skill, incident and outcome. There is no handover kind or save/resume operation in the inspected model/API. Incidents do not establish seven-day expiry, checkout-mismatch display or the required separate handover view. [Models: `KINDS`](https://github.com/DrDroidLab/hindsight/blob/bb8704fb6a3ed4e91877e244b2aea6360662621d/src/hindsight/models.py#L52), [API](https://drdroidlab.github.io/hindsight/api/) |
| Lifecycle and retries | Rejected clues are excluded, but proposed and stale clues remain visible. Capture IDs and promotion operation IDs supply retry primitives; the project's proposal/handover/acceptance retry guarantees, expiry and applicability filters remain unproven or absent from the documented contract. [Content model](https://github.com/DrDroidLab/hindsight/blob/bb8704fb6a3ed4e91877e244b2aea6360662621d/docs/content-model.md), [API](https://drdroidlab.github.io/hindsight/api/) |
| Review boundary | In normal UI mode, write scope also permits review: `review()` calls `get(..., write=True)`, which checks `identity.can_write(scope)`. Keeping review out of MCP therefore does not separate the agent's credentials from backend review access. `REVIEW_MODE=git` disables native review and delegates it to a protected trusted branch; enforcement and server/agent filesystem separation would need a concrete deployment test. [Security](https://drdroidlab.github.io/hindsight/security/), [domain](https://github.com/DrDroidLab/hindsight/blob/bb8704fb6a3ed4e91877e244b2aea6360662621d/src/hindsight/domain.py#L417), [Git review operations](https://github.com/DrDroidLab/hindsight/blob/bb8704fb6a3ed4e91877e244b2aea6360662621d/docs/operations.md#external-git-review-ceremony) |
| Portability and recovery | Git preserves knowledge history, but private auth/operation state is separately durable. The documented restore backs up both and rebuilds the index. No full-contract export/import or restore, including this project's proposals and handovers, was demonstrated here. [Backup procedure](https://github.com/DrDroidLab/hindsight/blob/bb8704fb6a3ed4e91877e244b2aea6360662621d/docs/operations.md#backup-and-restore) |

The immediate decision is therefore the implementation scope, not write-tool activation. Basic Memory's transaction hook can support the tested atomic history extension, while Hindsight supplies more review machinery with different trust and recall semantics. Neither inspected configuration supplies the complete target workflow. Before building a policy service or extending a candidate, choose which component will own proposals, durable revisions, handovers, retry state and the protected reviewer boundary; retain all gates unless a requirement change is explicitly approved. The current work authorizes neither a new engine nor a migration.
